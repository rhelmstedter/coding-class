** Part 2: Be the Code-Maker

| Secret code | Guess   | Black | White |

| B G R Y     | B R Y P |     1 |     2 |

Last row: the first R is in the right position (1 black). The secret has only one more R, so only one of the two remaining R pegs in the guess can score, and it scores white. The G is in the wrong position (white). A peg in the secret code can only be matched once. This is the detail students most often miss, and it is the reason Bagels forbids repeated digits.

* Bagels: Writing the Algorithm

** Part 2: Be the Code-Maker

| Guess | Clues            |
|-------+------------------|
|   843 | Fermi Pico       |
|   123 | Pico             |
|   284 | Fermi Pico Pico  |
|   567 | Bagels           |

1. Compare each digit of the guess with the digit in the same spot of the secret. If they match, it is a Fermi. If not, check whether the digit is anywhere else in the secret. If it is, it is a Pico. If no digit earns a clue, the clue is Bagels.
2. The 2. It is the only digit in the right spot. Listing the clues in order would tell the guesser which spot each clue belongs to, which gives away too much.

** Part 3: Write the Algorithm

Sample, matching =bagels.py=:

1. Display the instructions.
2. Repeat until the player is done playing:
   - Generate a secret number with no repeated digits.
   - Tell the player how many digits it has and how many guesses they get.
   - Repeat until the guess is correct or the player is out of guesses:
     - Get a valid guess from the player.
     - Display the clues, or "You got it!" if the guess is correct.
     - Count the guess.
   - If the player ran out of guesses, display the secret number.
   - Ask whether they want to play again.
3. Thank the player for playing.

1. Sequencing: steps 1 and 3, and the steps inside each loop, run in order. Selection: deciding whether the guess is correct, whether the player ran out, and whether to play again. Iteration: the two loops, one for each game and one for each guess.
2. The player guesses correctly, or runs out of guesses. The inner loop stops on either, and only running out reveals the secret number.
3. Answers vary.

** Part 4: AP Pseudocode

Sample:

#+begin_example
DISPLAY(instructions)
playing ← true
REPEAT UNTIL(NOT playing)
{
   secret ← generateSecret()
   numGuesses ← 1
   correct ← false
   REPEAT UNTIL(correct OR numGuesses > MAX_GUESSES)
   {
      guess ← getGuess()
      DISPLAY(getClues(guess, secret))
      correct ← isCorrect(guess, secret)
      numGuesses ← numGuesses + 1
   }
   IF(NOT correct)
   {
      DISPLAY(secret)
   }
   DISPLAY("Do you want to play again?")
   IF(INPUT() = "no")
   {
      playing ← false
   }
}
DISPLAY("Thanks for playing!")
#+end_example

1. AP pseudocode has no =break=, so winning becomes part of the stopping condition: =REPEAT UNTIL(correct OR numGuesses > MAX_GUESSES)=. =bagels.py= uses =break= for both loops; comparing the two is a good discussion.

* Bagels Notebook: Exploring the Program

Each answer was checked by making the change to =bagels.py= and running it.

1. The secret number and every guess have that many digits. With 1 digit the game is mostly luck. With 10, every digit is used, so every guess earns only Fermis and Picos, and the game is about order.
2. Players get that many guesses. With 1 the game is almost unwinnable; with 100 it is hard to lose.
3. The secret number stops at 10 digits, because there are only ten digits to shuffle and the slice cannot take more than the list has. =get_guess()= still demands =NUM_DIGITS= digits, so no guess can ever match and the game cannot be won.
4. The secret number is always 123, so typing 123 wins on the first guess.
5. =UnboundLocalError: cannot access local variable 'num_guesses' where it is not associated with a value=. The =while= loop checks =num_guesses= before anything has been put in it.
6. The secret number is always 012, the first three digits in order.
7. A correct guess shows =Fermi Fermi Fermi= instead of =You got it!=. The game still ends, because =main()= checks =guess == secret_num= on its own.
8. The guess count never goes up. Every guess is labeled =Guess #1=, and the player never runs out of guesses.

* The Caesar Cipher on Paper

** Part 1: Encrypt

1. =KHOOR ZRUOG=
2. =CHEUD=. Z is index 25, and $25 + 3 = 28$, which is past the end of the alphabet. Wrap around to the start: 28 becomes 2, which is C.
3. =ZIDRYX SC PEX=
4. If the sum is 26 or more, subtract 26. The rule that works for every letter is "divide by 26 and keep the remainder," which is exactly what =%= does in Python: =(index + key) % 26=.

** Part 2: Decrypt

1. =BE PROACTIVE=
2. =NO WHINING=
3. Subtracting the key can give a negative number. In question 1 that happens at A (index 0) and C (index 2), so add 26: $0 - 7 + 26 = 19$ (T) and $2 - 7 + 26 = 21$ (V). In question 2 it happens at every letter. In Python, =(index - key) % 26= already handles this.

* The Vigenère Cipher on Paper

Students need a printed copy of =Vigenere_square.svg=.

** Part 1: Encrypt

1. =JSOPQ KRVNR=. The key letters line up as C O D E C, then O D E C O.
2. =EI XABOIYW SBO EI AJCLFXTNS.= The key letters line up as DE LSOLDEL SOL DE LSOLDELSO.

** Part 2: Decrypt

1. Go to the key letter's row, find the ciphertext letter in that row, and read the letter at the top of that column.
2. =NO WHINING, NO COMPLAINING, NO EXCUSES.=

** Part 3: Your Own Message

1. Answers vary.
2. Answers vary.

** Part 4: Compare

1. The two Ls became O and P, because they were encrypted with different key letters (D and E). In a Caesar cipher both would become the same letter.
2. No. The first R came from O (with key letter D) and the second came from D (with key letter O).
3. In a Caesar cipher a letter always turns into the same letter, so patterns in the message survive. In Vigenère the same plaintext letter can become different ciphertext letters, and the same ciphertext letter can come from different plaintext letters.
4. =CODECODE=. Column A of the square is the same as the row labels, so encrypting A gives the key letter back. Encrypting a run of As leaks the key.
5. Row D is the Caesar cipher with key 3. Every row is a Caesar cipher, so a Caesar cipher is a Vigenère cipher with a one-letter keyword.

** Part 5: Think Like a Programmer

1. Row C shifts every letter 2 places and row O shifts every letter 14 places. A key letter's number is its position in the alphabet counting from 0, which is its index.
2. D. The keyword repeats every 4 letters, so divide the position by 4 and look at the remainder. Counting from 0 the way Python does, the 23rd letter is at index 22, and $22 \bmod 4 = 2$, which is D.
3. The key becomes a word, so =get_key()= changes, and =translate_message()= has to look up a different shift for each letter and keep track of which key letter comes next. =main()=, =get_mode()=, =get_message()=, and =print_message()= stay the same.
